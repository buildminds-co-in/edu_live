## Changes
- **Fix: large PDF uploads failed in prod** (`VECTOR_UPSERT_ERROR … oversized metadata … 46834 bytes`). Cause: the enrichment model intermittently loops on tables (space padding, or one separator growing to 48,000 characters), about 4 in 5 runs on one Science paper. Fixes: prompt forbids padding/long separators/repetition; `max_tokens` per page; filler, padding and repeated-line cleanup; a runaway page falls back to plain text; one retry when under half the pages came back. Chunker safety net keeps every chunk under the Vectorize metadata limit (normal chunks unchanged).
- **Question papers:** answers matched by question number within the same paper's answer key; official answers never copied onto changed questions; answer-key files get no question slots when their paper is selected (fixes papers missing whole sections); placeholder answers dropped; mark tags kept out; exact question count in the prompt; prompt version in the cache key so cached papers regenerate.
- **Answer keys:** strict structured output with one entry per question and one retry; JSON repair for LaTeX escapes, raw line breaks and in-text quotes. Maths answer keys were failing every time (also on v1.1.0); now complete 4/4.
- **Chat and explainer:** questions, options and assertion/reason statements from exam papers are not treated as facts; mark tags and tutor notes left out.
- **Dashboard:** a chapter name is required when a document is included in question papers (also enforced by `/ingest`).
- **Student app:** question-paper marks dropdown offers 60 instead of 70.
- **Dashboard, Transactions tab:** compact list of every transaction (time, feature, question, model, tokens in/out, cost) with a feature filter and 50/100/200 rows; clicking a row loads its details (chips for path, model, tokens in/out, cost, style, grounded in, retrieval mode, JEV; the retrieval ranking table; LLM input and output side by side). New routes `GET /admin/transactions/recent` and `GET /admin/transactions/:id`; the old `/admin/transactions` is unchanged.
- **Dashboard, Costing tab:** ranges All time / 2 hours / 1 day / 3 days / 7 days / 1 month; totals (requests, tokens, input, output, cost); per-model table with rates; per-feature table with share of cost; pricing reference.
- **Cost tracking now covers every model call:** question-paper generation, answer keys and PDF enrichment are recorded in `transactions` (they weren't before, so earlier costing under-reported). Chat records its answer style; the explainer records grounded-in and retrieval mode.

## Known issues
- **Science papers above 60 marks can come back a few questions short** with the new generation prompt (80 marks: short in about half the runs). 60 is now the highest option offered. A follow-up should fill missing slots in a second call.
- **Enrichment can misread a PDF** (sample Maths paper: option 1/3 read as 3/4; a graph's x-axis crossings), and question papers then inherit the error. A follow-up could compare numbers against the plain-text extraction.
- A flawed question (as marked by the official key) can still be reused; its placeholder answer is dropped and the answer key works out an answer instead.
- Maths answer keys take 60–140 s. A long request can drop the browser connection; the key is still saved, and clicking again returns it at once.
- Chat can't find a question by its number ("Q31 of the Science test paper"); ask by content instead.
- Embedder and reranker read only the first 512 tokens of a chunk; some answer-key and LaTeX-heavy chunks run to about 690. Token-aware chunk sizes are a follow-up.
